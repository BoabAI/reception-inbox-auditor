What it does

One scheduled Function. Three steps. No new app for the receptionist to learn — the output is a familiar SharePoint list.

Step 1

Watch the mailbox

Polls a shared M365 mailbox every 5 minutes via Microsoft Graph using a least-privilege app registration — Mail.Read scoped to that one mailbox only.

Step 2

Classify with Azure OpenAI

Sends subject, sender, and a short preview to gpt-4.1-nano in Australia East. Returns one of Referral or Other, plus a sub-category. Full email bodies are never stored.

Step 3

Log to SharePoint

Upserts into a SharePoint list, deduped by Internet Message ID. Receptionist works directly in the list — adds notes, marks status, never touches the AI.

Australian medical data

Designed for Australian Privacy Act compliance

Patient data is sensitive personal information under the Privacy Act 1988. This system is built so that data never leaves the customer's tenant or Australian sovereign territory.

● Single-tenant deployment

Every install lives inside the customer's own Azure subscription and Microsoft 365 tenant. BoabAI never holds customer credentials, data, or secrets. We deliver code; the customer owns the runtime.

● Data stays in Australia (APP 8)

Azure OpenAI, Function App, Storage, Key Vault, and SharePoint all run in Australia East. No cross-border data flow. Satisfies APP 8 obligations for sensitive health information.

● Least-privilege by default

Mail.Read is scoped to one mailbox via an Application Access Policy. Sites.Selected is scoped to one SharePoint site. Secrets live in Key Vault. Runtime auth uses managed identity.

● Minimal data exposure

The classifier only sees subject, sender, and a short preview. Full email bodies are not sent to the model and are not persisted by this system — they remain in Exchange Online where they always were.

Australian Privacy Principles alignment

APP 1 Open and transparent management — a Compliance & Privacy SharePoint page is provisioned at install.
APP 5 Notification of collection — only metadata + subject + preview are read; never full bodies.
APP 6 Use and disclosure — classification only, no secondary purpose.
APP 8 Cross-border disclosure — all resources in Australia East. No data leaves AU.
APP 11 Security — Key Vault for secrets, managed identity, narrow RBAC.
Audit Every classification is logged with the model version and prompt hash for retrospection.

How to implement

Wall-clock install is around 45 minutes once prerequisites are ready. Ongoing cost is roughly $1–$5 AUD per month on the customer's own Azure subscription.

Prerequisites

  • ✓Azure subscription with Owner permission for the deployer
  • ✓Azure OpenAI resource provisioned in Australia East, with gpt-4.1-nano deployed (quota approval can take 24–72 hours)
  • ✓An existing SharePoint site (e.g. /sites/Reception) — the list and hub page get provisioned into it
  • ✓The watched mailbox converted to Shared Mailbox type (one Exchange Online command)
  • ✓Global Admin available for ~10 minutes to grant consent and run one PowerShell command
  • ✓m365, az, func Core Tools v4, and bun installed on the engineer's workstation

Day-of install

# Clone the repo
git clone https://github.com/BoabAI/reception-inbox-auditor.git
cd reception-inbox-auditor

# Sign in to the customer's tenant + subscription
m365 login
az login

# Idempotent setup CLI — walks 11 steps,
# prompts for confirmation between each.
bun install
bun run package:init

The setup CLI creates the app registration, applies the Application Access Policy, grants Sites.Selected, deploys the Bicep template (Function App + Storage + Key Vault + RBAC), provisions the SharePoint list + hub page, and publishes the Function code.
